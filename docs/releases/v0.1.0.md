# wakeproxy v0.1.0

Initial public release of wakeproxy.

## Highlights

- Password-gated reverse proxy for a single upstream application
- Explicit Wake-on-LAN start flow instead of automatic wake on every unauthenticated hit
- Readiness checks that wait for reachability and HTTP health before releasing traffic
- Support for proxied HTTP requests and websocket upgrades
- Small operational footprint with in-memory sessions and a systemd-first deployment model

## Included in this release

- Consistent `wakeproxy` naming across the crate, binary, docs, templates, and runtime configuration
- `WAKEPROXY_*` environment variable namespace
- MIT license
- GitHub Actions CI and tagged release automation
- `examples/wakeproxy.service` for systemd deployments
- Clearer repo structure, including a split `web` module and shared HTTP redirect/cache helpers

## Security and behavior notes

- Session state and login-attempt tracking are memory-backed by design
- Gateway auth cookies are not forwarded upstream
- Proxy header trust is opt-in and constrained by an explicit trusted IP list
- POST actions rely on same-origin request validation

## Suggested upgrade/install path

- Build with `cargo build --release`
- Install the binary as `/usr/local/bin/wakeproxy`
- Copy `examples/wakeproxy.service` into `/etc/systemd/system/`
- Create `/etc/wakeproxy/wakeproxy.env` with your real `WAKEPROXY_*` values
- Start with `sudo systemctl enable --now wakeproxy`

## Project scope

wakeproxy is intentionally not a full IAM platform, generic reverse proxy control plane, or multi-service router. It is designed for one protected upstream application that may need Wake-on-LAN before access.
